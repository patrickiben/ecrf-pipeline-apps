eCRF pipeline apps

Four independent Streamlit programs that read clinical eCRF extracts and write outputs a person reviews: the Coding QC assist proposes dictionary codes for adverse-event verbatims, the De-identification review assist flags and redacts identifiers in free text, Participant risk screening ranks participants against built-in safety criteria, and Central statistical monitoring looks for outliers, drift and unusual notes. Each app is a separate program with its own audit log, so a run can be reproduced from its audit alone. All four also run in your browser on the bundled synthetic data.

Synthetic data only. Everything bundled with these apps is synthetic: no real patients, no real study and no licensed dictionary. The demo dictionary uses 99-prefixed placeholder codes; it is not MedDRA. Evidence label: Tools built. These are evaluated prototypes, not validated systems.

Run the apps in your browser

Each page runs the same Python program inside your browser tab with stlite (Streamlit on Pyodide, Python compiled to WebAssembly), so there is no server to sleep, wake or sign in to. The page downloads Python and the app's packages from a CDN, fetches the program and its synthetic data from this site, and runs everything on your device.

  • Coding QC assist (meddra_app.py): proposes MedDRA-style terms for adverse-event verbatims from a demo dictionary. On held-out synthetic verbatims its stand-in ranked the right preferred term first for 54% (the real model path: 78%).
  • De-identification review assist (phi_app.py): flags and redacts identifiers in free text. On held-out synthetic text its stand-in left 108 of 308 identifiers readable (the real model path: 91 of 308); every output needs human review.
  • Participant risk screening (risk_app.py): a safety listing ranked by rule-based safety and discontinuation scores, which are capped rule sums, not probabilities.
  • Central statistical monitoring (anomaly_app.py): checks for numeric outliers, distributional drift and unusual free-text notes.

Each opens in hosted mode on the bundled synthetic sample data: every data input is locked, a banner says so, and the audit records hosted_mode=true. Click Execute, then save results with the download buttons. The first visit downloads about 30 MB. For real data, run the apps locally (see the README).

Privacy. Runs in your browser; files are processed on your device and not uploaded by the app; the page is downloaded from GitHub Pages and the CDN, which see your IP address; synthetic data only; not a validated or Part 11 system.

The four apps

The coding, de-identification and risk apps read the same synthetic cut folder without interfering; the monitoring app reads its own longitudinal demo, because drift needs a time axis. All four accept CSV, and SAS .sas7bdat when pyreadstat is installed.

Coding QC assist

meddra_app.py

Reads
The one verbatim column you select (AETERM or a synonym), plus a dictionary as a flattened CSV or an .asc release.
Writes
ae_coded.csv (top three candidates per verbatim, with the LLT to SOC path) and audit_log.csv.

De-identification review assist

phi_app.py

Reads
Every non-numeric column, found by content rather than by name. No dictionary.
Writes
phi_flags.csv (one row per scrubbed span), sanitized/<domain>.csv and audit_log.csv. Both data outputs still contain the identifiers (the span text, and the original column beside the scrubbed copy).

Participant risk screening

risk_app.py

Reads
Safety domains (ae, lb, eg, vs, pe), classified by content and scored against built-in [SI] criteria. No SAP file.
Writes
risk_scores.csv (safety and discontinuation scores with contributing factors) and audit_log.csv. Decision support, not a clinical determination.

Central statistical monitoring

anomaly_app.py

Reads
Longitudinal files aligned by USUBJID: numeric columns, plus optional visit, lab/site and free-text columns.
Writes
anomalies.csv, drift.csv, lab_drift.csv, lab_compare.csv, text_anomalies.csv and audit_log.csv.

The four-tier chain

Every app runs the same discipline: four tiers in sequence, each handing named, readable columns to the next, so a decision is a row of numbers a reviewer can inspect and its threshold is a parameter a reviewer can move.

  1. Tier 1, intake. Aligns each row to its participant, copies every value through unchanged (missing stays missing) and locates the columns to read by content.
  2. Tier 2, retrieval and extraction. Proposes and measures: candidate dictionary terms, typed identifier spans, or per-participant signals. It decides nothing.
  3. Tier 3, context and calibration. Adds calibrated probabilities, an ambiguity score, aggregate risk scores or drift distances.
  4. Tier 4, decision. Applies an explicit rule to the earlier tiers' columns only: the auto-commit gate (default 0.88), the redaction gate (default 0.85), or the risk and anomaly categories.

Stand-in [SI] versus real

No trained weights ship with this repository, so the model tiers run as labeled deterministic stand-ins, tagged [SI] in the banner and in every audit row, with the same output columns the real components would produce. Run locally with the open-source runtimes (Cactus Needle3, hnswlib, Laya, XGBoost) and a models dir, and the coding and de-identification apps switch to their real path tier by tier, with no network access; a tier shows REAL only when its artifact loads, and an artifact that cannot be used stops the run rather than being replaced by a stand-in. The real path cannot run in the browser. What it does on synthetic data is measured in the evaluation case study: better than the stand-in on misspellings and untitled names, no better on colloquial verbatims, and about 0.4 s per verbatim on a CPU. Optional packages also turn on real detectors in the monitoring app when it runs locally: scikit-learn adds an Isolation Forest, and POT with scipy runs Sinkhorn optimal-transport drift.
